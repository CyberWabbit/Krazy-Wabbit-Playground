# Adapting the engines to the M-VAVE FM-1

This browser application contains no FM-1 firmware. A port is a separate embedded project with a target-specific build, audio implementation, and hardware validation.

1. **Use the generators as the reference.** Read `engine()` in `src/music.js` for MUTINY and PARASITE, and `newEcosystem()` in `src/ecosystem.js` for ECOSYSTEM. Capture seeded event traces with the existing tests as a behavioral reference. Preserve step ordering, phrase memory, lifecycle thresholds, and note-off semantics.
2. **Prototype a portable core.** Port generator state and event scheduling to C with bounded storage. Convert event times to audio sample positions or a hardware monotonic clock. Reimplement the synthesis, UI, and I/O around that core. Use fixed-point synthesis and measured voice budgets where the target requires them. Replace browser entropy with a device entropy source and retain a deterministic seed option for tests.
3. **Choose and audit the board support.** Compare M-VAVE’s official FM1 Open SDK with a community baseline such as Dinghy. Pin revisions and check compiler, SDK, memory map, package format, and redistribution terms for the chosen release. Official application and binary SDK terms differ. Community firmware has its own license and attribution requirements. [M-VAVE FM1 Open](https://github.com/m-vave/fm1_open) · [Dinghy](https://github.com/zvenson/dinghy)
4. **Verify MIDI routing and cleanup.** The FM-1’s TRS MIDI jack is input only. Confirm device-mode USB MIDI output on the selected stack and use a compatible host for peripheral-to-peripheral routing. Budget the MIDI queue, pair every note-on with a note-off, and test stop, disconnect, and route changes. [Foma FM-1 I/O notes](https://github.com/konsumer/foma#build-options)
5. **Test before any flash.** Build a minimal target package and inspect its link map. Use `fm1-emu` for boot, screen, panel, and simulated audio checks. Separately verify the unit’s hardware revision, installed firmware, and supported rollback procedure. Back up user data and use an owner-approved test unit for any first flash. Audio performance, transport timing, and recovery require hardware validation. [FM-1 emulator](https://github.com/joakimeriksson/fm1-emu)

The Roland S-1 test applies to browser PARASITE via Chrome and USB-MIDI. It does not validate an FM-1 port.
